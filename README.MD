## 设备预测性维护看板解决什么问题？

面向制造业，围绕“模拟读数预警、定期保养与备件管理”提供可操作的演示系统。当前交付状态：**已完成中台功能验收；用于业务演示，未完成生产部署验收**。

## 系统架构

```text
浏览器页面 → JavaScript 校验与业务计算 → localStorage
浏览器页面 ← 列表 / 指标 / CSV ← 当前浏览器中的演示记录
```

cockpit 用于 AI 开发过程，不是此系统运行的必需服务。本系统没有因为使用 AI 开发而自动接入运行时大模型。

## 本地运行

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 http://127.0.0.1:8000/index.html 。无需构建或后端依赖，也可直接打开 index.html；建议固定 HTTP 地址，避免浏览器存储来源变化。

## 操作步骤

1. 初始电解循环泵运行 1240 h、保养点 1200 h，因此自动生成待办 SIM-W0001；反复检查、刷新不会重复生成。
2. 新增设备，填写虚构 SIM-E 编号、车间、累计时长、周期和温度/振动阈值。支持编辑；累计时长不可回退，有待处理工单时不能修改保养点绕过工单。
3. 点击“模拟采集”，填写累计时长、温度和振动。温度或振动达到阈值即提醒；同一参数连续三次严格上升产生趋势提醒。选择趋势设备查看最近 12 条折线及全部历史读数。
4. 运行时长达到保养点，按车间自动分配维修组；可调整派工。点击“完成保养”，选择备件数量及说明。超库存拒绝整个提交；成功后扣库存、记录流水、归档工单，并将下次保养设置为当前时长加保养周期。
5. 备件支持新增、编辑名称/提醒阈值、入库和领用。数量为整数，变动数量必须大于 0；不用备件完成保养时数量为 0。库存小于等于阈值时提醒。
6. 搜索编号或名称，并组合车间、状态筛选。CSV 导出当前筛选的设备台账（并非全量备份）。重置需确认，取消不改变数据。


- 明示“演示数据·仅当前浏览器保存”；企业名为某企业、车间为一二三车间、编号均虚构。
- localStorage 键：`development-10-maintenance-v1`。清除网站存储会丢失数据；不支持多人/多标签并发合并，无法作为生产数据库。
- 全部读数由用户手工模拟，没有连接真实传感器、外部接口或训练预测模型。趋势提醒仅是明确的三点递增规则，不输出故障概率或剩余寿命。
- “自动派工”是页面加载或用户操作后的本地规则重算，不发送外部消息，无后台定时任务。保养按累计运行小时，不按日历日期。
- 顶部统计为全台账；筛选只作用于设备表及其 CSV，趋势可独立选择设备。
